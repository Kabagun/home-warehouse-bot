# home-warehouse-bot — MCP

Самостоятельный MCP-сервер для домашнего склада. Агент получает структурированные данные и вызывает конкретные операции учёта. Telegram, токен бота и Google Таблицы для этой версии не требуются.

## Три версии

| Ветка | Версия |
| --- | --- |
| `main` | Исходный Telegram-бот |
| `telegram-bot` | Новая Telegram-версия с общими правилами учёта и дополнительным MCP |
| `mcp-only` | Эта версия: самостоятельный MCP без Telegram |

Переключение: `git switch <ветка>`. SQLite-базы и локальные настройки не входят в Git. Для каждой версии используйте отдельный путь к базе: переключение ветки не откатывает её схему и данные.

## Что разрешено агенту

| Данные и операции | MCP-инструменты |
| --- | --- |
| Дома | `list_households`, `create_household` |
| Склады | `list_stores`, `create_store` |
| Остатки | `list_items`, `add_item`, `change_item_quantity`, `set_item_quantity` |
| Минимумы и покупки | `set_item_minimum`, `shopping_list` |
| Архив | `archive_item`, `restore_item` |

У каждого инструмента фиксированная схема входных и выходных данных. Код проверяет доступ к дому, конечность и знак количества, совместимость единиц и состояние архивной позиции. Например, к позиции в килограммах можно добавить 500 граммов; литры с килограммами смешать нельзя. Список покупок включает активные позиции с остатком меньше или равным минимуму.

Личность пользователя и путь к базе задаёт оператор при запуске. Аргументы инструментов не позволяют сменить их. Сервер не предоставляет SQL, выполнение кода, доступ к произвольным файлам или безвозвратное удаление товаров. Архивирование сохраняет количество и минимум, восстановление возвращает позицию в учёт.

Эти ограничения действуют через данный MCP-сервер. Если отдельно дать агенту прямой доступ к файлу базы или учётной записи владельца, такие права выходят за границы MCP.

## Установка

Требуется Python 3.11 или новее. Пример для PowerShell 7:

```powershell
git switch mcp-only
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
```

Для Linux используйте `.venv/bin/python`. Основная зависимость — официальный [MCP Python SDK](https://py.sdk.modelcontextprotocol.io/). Отдельная установка Telegram-библиотеки не нужна.

## Новая база

Инициализация выполняется оператором один раз, до подключения агента:

```powershell
.\.venv\Scripts\python mcp_server.py init --database-path ./home_warehouse.sqlite3 --user-id 1 --household-name "Мой дом"
```

Команда создаёт локального пользователя, дом и обычные склады «Основной», «Морозилка», «Холодос». Число `1` — пример локального идентификатора, регистрации в Telegram нет. Повторная инициализация с тем же пользователем сохраняет существующие дома, названия и остатки. В заполненную базу с другим пользователем эта команда новую личность не добавляет.

Инициализация не доступна как MCP-инструмент. Обычный запуск сервера требует существующую базу и зарегистрированного пользователя и не создаёт их автоматически.

## Подключение агента

Транспорт — stdio: MCP-клиент запускает сервер как дочерний процесс. HTTP-порт и постоянно работающий systemd-сервис для этого не нужны.

Пример для клиентов с настройкой `mcpServers`:

```json
{
  "mcpServers": {
    "home-warehouse": {
      "command": "C:/path/to/home-warehouse-bot/.venv/Scripts/python.exe",
      "args": ["C:/path/to/home-warehouse-bot/mcp_server.py"],
      "env": {
        "DATABASE_PATH": "C:/path/to/data/home_warehouse.sqlite3",
        "MCP_USER_ID": "1"
      }
    }
  }
}
```

Замените пути и пользователя на свои. На Linux используйте абсолютный путь `.venv/bin/python`. Реальную конфигурацию храните вне Git. Переменные передаёт клиент; сервер не загружает `.env` автоматически. Файл `.env.example` содержит только образец переменных.

Для ручного запуска в PowerShell:

```powershell
$env:DATABASE_PATH = (Resolve-Path ./home_warehouse.sqlite3).Path
$env:MCP_USER_ID = "1"
.\.venv\Scripts\python mcp_server.py serve
```

Запуск без `serve` тоже использует stdio. Сам по себе запущенный процесс ожидает MCP-запросы на стандартном вводе. Служебные ошибки направляются в stderr.

## Подключение по HTTPS

Для удалённого клиента используйте веб-режим из `app_runtime.py`. Платформа запускает корневой сценарий `run` и завершает TLS на своём HTTPS-входе. MCP endpoint — `/mcp`; клиент передаёт токен в заголовке `Authorization: Bearer …`. При настроенном публичном HTTPS-адресе доступен также OAuth для подключения из ChatGPT. Оба способа открывают те же инструменты от имени настроенного владельца. `/healthz` отвечает только статическим статусом для GET и HEAD и не возвращает данные учёта.

Веб-режим использует те же 12 инструментов учёта, что и stdio, и stateless HTTP-транспорт. В запуске через `app_runtime.py` также доступен защищённый инструмент `get_profile`: он возвращает имя «Склад» и метку «Дом» для распознавания подключения в ChatGPT. Это не делает SQLite учёт безсостояниевым: изменения по-прежнему сохраняются в базе. Новых ролей, SQL-инструментов и административного доступа нет. Для stdio токен не нужен.

Перед запуском настройте переменные окружения платформы:

| Переменная | Назначение |
| --- | --- |
| `APP_DATA_DIR` | Обязательный путь к существующему приватному постоянному каталогу. В нём должна быть существующая база `home_warehouse_bot.sqlite3`; здесь же хранятся `mcp-settings.json` и резервные копии. |
| `DATABASE_PATH` | Необязательный путь к существующему файлу базы непосредственно в `APP_DATA_DIR`. По умолчанию используется `$APP_DATA_DIR/home_warehouse_bot.sqlite3`. |
| `HOST`, `PORT` | Адрес и порт, которые назначает платформа. Без них используются `127.0.0.1` и `8000`. |
| `MCP_RELEASE_ID` | Обязательный идентификатор текущего релиза длиной 1–128 символов из букв ASCII, цифр, точки, подчёркивания и дефиса (кроме `.` и `..`); задавайте новое значение для каждой выкладки. |
| `MCP_BOOTSTRAP_FILE` | Путь к закрытому JSON-файлу для первичной настройки токена и владельца. |
| `MCP_PUBLIC_URL` | Origin публичного HTTPS-адреса без пути, например `https://warehouse.example.invalid`. Для публичного размещения укажите его, чтобы разрешить адрес платформы в проверках Host/Origin; локальному loopback-запуску он не нужен. |

Каталог `APP_DATA_DIR` должен быть закрыт от других приложений и пользователей и сохраняться при перезапуске и обновлении. `DATABASE_PATH`, если задан, должен указывать на существующий файл непосредственно в этом каталоге. Перед миграциями каждого релиза приложение сохраняет приватную копию базы в `backups/before-mcp-<MCP_RELEASE_ID>.sqlite3`. Настройте резервное копирование каталога отдельно от размещённой службы.

Для первой настройки платформа передаёт `MCP_BOOTSTRAP_FILE` как закрытый JSON-файл; на POSIX-системах у файла не должно быть никаких прав для группы и остальных пользователей. `auth_token` — случайно сгенерированный токен длиной не менее 32 символов. `user_id` должен ссылаться на существующего локального пользователя. Пример содержимого с заменённым токеном:

```json
{
  "auth_token": "<GENERATED_SECRET>",
  "user_id": 1,
  "public_url": "https://warehouse.example.invalid"
}
```

Вместо `user_id` можно явно указать `"select_single_owner": true`: запуск завершится ошибкой, если в базе нельзя однозначно выбрать единственного владельца. `public_url` необязателен; переменная `MCP_PUBLIC_URL`, если задана, имеет приоритет над URL из файла и сохранённым значением. После первой настройки приложение хранит стабильные параметры в приватном `APP_DATA_DIR/mcp-settings.json`; этот файл тоже содержит токен, поэтому оставляйте каталог закрытым. Удалите исходный файл первичной настройки из секрета платформы после успешного запуска. Передавайте токен клиенту только через его защищённое хранилище учётных данных; не помещайте его в URL, аргументы командной строки, Git или логи.

При обновлении приложение один раз добавляет в этот файл случайный `profile_id`, не меняя токен, владельца или базу. Сохраняйте его вместе с остальными параметрами: он остаётся прежним при перезапуске, обновлении токенов и переподключении. Если сохранённый `profile_id` повреждён, запуск завершается ошибкой вместо создания другой идентичности.

Проверки Host/Origin включены на MCP endpoint; указывайте точный публичный origin платформы в `MCP_PUBLIC_URL`. Публикуйте сервис по HTTPS. После успешной выкладки сохраните созданную резервную копию вместе с релизом: возврат старого кода сам по себе не отменяет миграцию схемы SQLite.

`deploy/app.yaml` содержит только общий манифест веб-приложения. Пример переменных без секретов находится в `.env.example`; он служит справкой и автоматически не загружается.

### OAuth для ChatGPT

В форме добавления пользовательского MCP-сервера укажите свой HTTPS-адрес с путём `/mcp` и выберите OAuth. Сервер публикует метаданные авторизации и защищённого ресурса, поддерживает регистрацию клиента и PKCE S256. На странице согласия перечислены все 12 операций учёта; произвольного доступа к коду, файлам и другим пользователям нет.

Перед подтверждением оператор создаёт одноразовый код в окружении приложения, от имени пользователя службы:

```powershell
.\.venv\Scripts\python mcp_oauth.py owner-code --data-dir C:/path/to/private-data --issuer https://warehouse.example.invalid
```

Введите код на странице согласия и нажмите «Разрешить доступ». Код действует пять минут и расходуется один раз; новый код заменяет предыдущий. Не используйте постоянный Bearer-токен вместо этого кода. Не сохраняйте код в репозитории или логах.

OAuth-состояние хранится отдельно от запасов в приватном `APP_DATA_DIR/oauth.sqlite3`. Коды, токены и секреты клиентов сохраняются как хеши. Access token действует час, refresh token — до 30 дней; обновление заменяет refresh token, а повторное использование старого отзывает выданную им цепочку. Для отказа от подключения используйте отключение приложения в клиенте с отзывом токена. Сохранение OAuth-файла между релизами позволяет продолжить существующее подключение.

## Существующая база

Сначала сохраните согласованный снимок SQLite и используйте отдельную копию для этой версии. Настройте `DATABASE_PATH` и `MCP_USER_ID` на существующего пользователя. Данные домов, участников, складов и товаров сохраняются; миграции применяются при запуске.

Исторические имена SQL-полей, включая `users.chat_id`, сохранены для совместимости с базами двух Telegram-версий. Они не требуют Telegram-подключения. Старая переменная `MCP_CHAT_ID` поддерживается как псевдоним `MCP_USER_ID`; при одновременной настройке значения должны совпадать.

Не запускайте старую версию на единственной копии базы, которую уже изменили более новые миграции. Обновление данных добавляет недостающие склады «Морозилка» и «Холодос» один раз; удалённые или переименованные после обновления склады повторно не появляются.

## Код и проверка

- `mcp_server.py` — CLI, настройка пользователя и типизированные MCP-инструменты.
- `mcp_http.py`, `mcp_oauth.py` — HTTPS, проверка Bearer-токена и OAuth-подключение.
- `inventory_service.py` — операции учёта и пересчёт единиц.
- `storage.py` — транзакции SQLite, миграции и проверки членства в доме.
- `storage_types.py` — модели данных и совместимость сохранённого состояния.
- `amounts.py` — единицы измерения, количество и разбор текстовых значений.

```powershell
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m pytest -q
.\.venv\Scripts\python -m compileall -q mcp_server.py inventory_service.py storage.py storage_types.py amounts.py
```

Тесты используют временные базы. Они проверяют изоляцию домов, миграции, единицы, архив, инициализацию и настоящий обмен сообщениями по stdio. Каталог `temp/` исключён из Git и обычного запуска тестов.
