# home-warehouse-bot — MCP

Самостоятельный MCP-сервер для домашнего склада. Агент получает структурированные данные и вызывает конкретные операции учёта. Telegram, токен бота и Google Таблицы для этой версии не требуются.

## Три версии

| Ветка | Версия |
| --- | --- |
| `main` | Исходный Telegram-бот |
| `telegram-bot` | Новая Telegram-версия с общими правилами учёта и дополнительным MCP |
| `mcp-only` | Эта версия: самостоятельный MCP без Telegram |

Переключение: `git switch <ветка>`. SQLite-базы и локальные настройки не входят в Git. Для каждой версии используйте отдельный путь к базе: переключение ветки не откатывает её схему и данные.

## Что разрешено агенту

| Данные и операции | MCP-инструменты |
| --- | --- |
| Дома | `list_households`, `create_household` |
| Склады | `list_stores`, `create_store` |
| Остатки | `list_items`, `add_item`, `change_item_quantity`, `set_item_quantity` |
| Минимумы и покупки | `set_item_minimum`, `shopping_list` |
| Архив | `archive_item`, `restore_item` |

У каждого инструмента фиксированная схема входных и выходных данных. Код проверяет доступ к дому, конечность и знак количества, совместимость единиц и состояние архивной позиции. Например, к позиции в килограммах можно добавить 500 граммов; литры с килограммами смешать нельзя. Список покупок включает активные позиции с остатком меньше или равным минимуму.

Личность пользователя и путь к базе задаёт оператор при запуске. Аргументы инструментов не позволяют сменить их. Сервер не предоставляет SQL, выполнение кода, доступ к произвольным файлам или безвозвратное удаление товаров. Архивирование сохраняет количество и минимум, восстановление возвращает позицию в учёт.

Эти ограничения действуют через данный MCP-сервер. Если отдельно дать агенту прямой доступ к файлу базы или учётной записи владельца, такие права выходят за границы MCP.

## Установка

Требуется Python 3.11 или новее. Пример для PowerShell 7:

```powershell
git switch mcp-only
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
```

Для Linux используйте `.venv/bin/python`. Основная зависимость — официальный [MCP Python SDK](https://py.sdk.modelcontextprotocol.io/). Отдельная установка Telegram-библиотеки не нужна.

## Новая база

Инициализация выполняется оператором один раз, до подключения агента:

```powershell
.\.venv\Scripts\python mcp_server.py init --database-path ./home_warehouse.sqlite3 --user-id 1 --household-name "Мой дом"
```

Команда создаёт локального пользователя, дом и обычные склады «Основной», «Морозилка», «Холодос». Число `1` — пример локального идентификатора, регистрации в Telegram нет. Повторная инициализация с тем же пользователем сохраняет существующие дома, названия и остатки. В заполненную базу с другим пользователем эта команда новую личность не добавляет.

Инициализация не доступна как MCP-инструмент. Обычный запуск сервера требует существующую базу и зарегистрированного пользователя и не создаёт их автоматически.

## Подключение агента

Транспорт — stdio: MCP-клиент запускает сервер как дочерний процесс. HTTP-порт и постоянно работающий systemd-сервис для этого не нужны.

Пример для клиентов с настройкой `mcpServers`:

```json
{
  "mcpServers": {
    "home-warehouse": {
      "command": "C:/path/to/home-warehouse-bot/.venv/Scripts/python.exe",
      "args": ["C:/path/to/home-warehouse-bot/mcp_server.py"],
      "env": {
        "DATABASE_PATH": "C:/path/to/data/home_warehouse.sqlite3",
        "MCP_USER_ID": "1"
      }
    }
  }
}
```

Замените пути и пользователя на свои. На Linux используйте абсолютный путь `.venv/bin/python`. Реальную конфигурацию храните вне Git. Переменные передаёт клиент; сервер не загружает `.env` автоматически. Файл `.env.example` содержит только образец переменных.

Для ручного запуска в PowerShell:

```powershell
$env:DATABASE_PATH = (Resolve-Path ./home_warehouse.sqlite3).Path
$env:MCP_USER_ID = "1"
.\.venv\Scripts\python mcp_server.py serve
```

Запуск без `serve` тоже использует stdio. Сам по себе запущенный процесс ожидает MCP-запросы на стандартном вводе. Служебные ошибки направляются в stderr.

## Существующая база

Сначала сохраните согласованный снимок SQLite и используйте отдельную копию для этой версии. Настройте `DATABASE_PATH` и `MCP_USER_ID` на существующего пользователя. Данные домов, участников, складов и товаров сохраняются; миграции применяются при запуске.

Исторические имена SQL-полей, включая `users.chat_id`, сохранены для совместимости с базами двух Telegram-версий. Они не требуют Telegram-подключения. Старая переменная `MCP_CHAT_ID` поддерживается как псевдоним `MCP_USER_ID`; при одновременной настройке значения должны совпадать.

Не запускайте старую версию на единственной копии базы, которую уже изменили более новые миграции. Обновление данных добавляет недостающие склады «Морозилка» и «Холодос» один раз; удалённые или переименованные после обновления склады повторно не появляются.

## Код и проверка

- `mcp_server.py` — CLI, настройка пользователя и типизированные MCP-инструменты.
- `inventory_service.py` — операции учёта и пересчёт единиц.
- `storage.py` — транзакции SQLite, миграции и проверки членства в доме.
- `storage_types.py` — модели данных и совместимость сохранённого состояния.
- `amounts.py` — единицы измерения, количество и разбор текстовых значений.

```powershell
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m pytest -q
.\.venv\Scripts\python -m compileall -q mcp_server.py inventory_service.py storage.py storage_types.py amounts.py
```

Тесты используют временные базы. Они проверяют изоляцию домов, миграции, единицы, архив, инициализацию и настоящий обмен сообщениями по stdio. Каталог `temp/` исключён из Git и обычного запуска тестов.
