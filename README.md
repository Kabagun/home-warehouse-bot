# home-warehouse-bot

В репозитории три версии:

| Ветка | Версия |
| --- | --- |
| `main` | Исходный Telegram-бот |
| `telegram-bot` | Новая Telegram-версия с общими правилами учёта и дополнительным MCP |
| `mcp-only` | Самостоятельный MCP-сервер для агента без Telegram |

Переключение: `git switch <ветка>`. Ниже описана версия `telegram-bot`.
База SQLite и локальные настройки хранятся вне Git и не переключаются вместе с ветками.

Telegram-бот для общего домашнего склада: лекарства, продукты, корм и бытовая химия.

## Возможности

- Несколько домов у одного пользователя: общий дом, родители, дача.
- Общий доступ к дому по коду приглашения.
- Несколько обычных складов внутри дома, в том числе «Морозилка» и «Холодос».
- Единый экран склада с товарами-кнопками и пагинацией.
- Добавление одной позиции или целого списка товаров, по одному товару в строке.
- Карточка товара с быстрыми кнопками количества по единицам, точным добавлением и списанием.
- Количество в штуках, таблетках, граммах, килограммах, миллилитрах, литрах и пользовательских единицах.
- Общий список `Купить` по всем складам текущего дома.
- Архив позиций с восстановлением прежнего остатка и минимума; ненужную позицию можно удалить безвозвратно.
- Автоматическое обновление открытых экранов у участников общего дома.
- Работа без автоматических сообщений и напоминаний.

## Навигация

Постоянная клавиатура содержит только главные разделы:

```text
[Склады] [Купить]
[Дом]     [Помощь]
```

Списки и действия текущего экрана находятся под сообщением. Переходы внутри раздела обновляют это же сообщение.

Рядом с каждым складом есть кнопка ⚙️: переименование и удаление доступны
сразу для выбранного склада. Удаление требует отдельного подтверждения.
В длинных списках показан номер страницы. В разделе `Купить` кнопка `Купил`
открывает ввод фактически купленного количества.

Быстрые кнопки в карточке товара показывают количество и единицу:

| Единица товара | Быстрый шаг |
| --- | --- |
| Штуки, таблетки и пользовательские единицы | 1 |
| Граммы и миллилитры | 100 |
| Килограммы и литры | 0,5 |

Для другого количества используйте `Списать` или `Добавить`.
Если единица товара изменилась, старая кнопка пересчитает совместимые единицы
или предложит обновлённые кнопки без изменения остатка.

## Быстрый ввод

Последний открытый склад используется для быстрых команд:

```text
+ Миг 8табл
- Миг 2табл
+ корм 9кг мин 500г
- корм 1,5кг
-- горох
```

Длинное тире `— горох`, которое Telegram может подставить вместо двух минусов, тоже переносит позицию в архив.

Минимум по умолчанию равен `1`. Позиция появляется в разделе `Купить`, когда остаток меньше или равен минимуму.

## Команды

- `/start` — открыть бот и постоянное меню.
- `/stock` — открыть список складов.
- `/buy` — открыть общий список покупок.
- `/homes` — открыть дома, участников и код приглашения.
- `/newhome Родители` — создать дом.
- `/renamehome Наш дом` — переименовать текущий дом.
- `/join ABC1234` — присоединиться к дому.
- `/help` — открыть справку.
- `/id` — показать ID своего чата для настройки MCP.

## Склады

«Морозилка» и «Холодос» — такие же записи в списке складов, как «Лекарства»,
«Кухня» или «Коридор». У склада есть название и список товаров. Новый склад
создаётся по названию, без выбора типа. Раздел `Купить` объединяет недостающие
товары из всех складов дома.

Разовое обновление данных добавляет недостающие склады «Морозилка» и «Холодос»
в существующие дома, сохраняя прежние склады, товары и выбранный склад.
Новые дома получают эти склады вместе с «Основным». Удалённые или переименованные
после обновления склады не создаются заново при каждом запуске.

## Локальный запуск

Требуется Python 3.11 или новее.

1. Создайте `.env` рядом с `bot.py`:

```text
TELEGRAM_BOT_TOKEN=токен_бота
DATABASE_PATH=home_warehouse_bot.sqlite3
```

2. Установите зависимости и запустите:

```powershell
git clone <repository-url> home-warehouse-bot
cd home-warehouse-bot
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
.\.venv\Scripts\python bot.py
```

## MCP: работа с ботом через агента

Локальный MCP-сервер даёт агенту доступ к тем же данным и правилам учёта,
что и Telegram-бот. Используется официальный [MCP Python SDK](https://py.sdk.modelcontextprotocol.io/)
и транспорт stdio. Сервер запускается отдельным процессом, ему не нужен токен Telegram.

1. Установите дополнительную зависимость:

   ```powershell
   .\.venv\Scripts\python -m pip install -r requirements-mcp.txt
   ```

2. Откройте бот, создайте дом или присоединитесь к существующему и вызовите `/id`.
3. Настройте MCP-клиент: укажите абсолютные пути к Python, серверу и **той же базе**,
   которую использует бот, и свой ID в `MCP_CHAT_ID`.

MCP читает переменные окружения процесса; передайте их через настройки клиента.
Файл `.env` используется при запуске Telegram-бота.

Пример для клиентов с конфигурацией `mcpServers` на Windows:

```json
{
  "mcpServers": {
    "home-warehouse": {
      "command": "C:/path/to/home-warehouse-bot/.venv/Scripts/python.exe",
      "args": ["C:/path/to/home-warehouse-bot/mcp_server.py"],
      "env": {
        "DATABASE_PATH": "C:/path/to/home-warehouse-bot/home_warehouse_bot.sqlite3",
        "MCP_CHAT_ID": "<your-telegram-chat-id>"
      }
    }
  }
}
```

На Linux используйте путь `.venv/bin/python`. Значения в примере — заполнители;
локальную конфигурацию с реальными ID и путями храните вне Git.

Сервер должен работать на машине, где находится SQLite-база бота. Каждый запрос
ограничен домами настроенного пользователя; передать чужой ID параметром инструмента нельзя.
Отсутствующая база или неизвестный пользователь считаются ошибкой настройки.
Изменения через MCP видны боту в общей базе; уже открытый экран Telegram можно
перечитать кнопкой `Обновить` или повторным открытием раздела.

Инструменты агента:

| Задача | Инструменты |
| --- | --- |
| Дома | `list_households`, `create_household` |
| Склады | `list_stores`, `create_store` |
| Позиции и остатки | `list_items`, `add_item`, `change_item_quantity`, `set_item_quantity` |
| Минимумы и покупки | `set_item_minimum`, `shopping_list` |
| Архив | `archive_item`, `restore_item` |

Количество можно передать в совместимых единицах: например, добавить `500 мл`
к позиции, учитываемой в литрах. Если единица не указана, для существующей позиции
используется её текущая единица, для новой — `шт`. Повторное добавление архивной
позиции начинает остаток заново; восстановление из архива возвращает сохранённый остаток.

## Устройство кода

- `storage_types.py` — общие модели дома, склада и товара.
- `storage.py` — SQLite, миграции, права доступа и изменения остатков.
- `amounts.py` — разбор количества, единицы измерения и пересчёт.
- `inventory_service.py` — общие операции учёта для Telegram и MCP.
- `panels.py` — тексты экранов и кнопки Telegram.
- `inventory_bot.py` — обработчики команд, кнопок и пошагового ввода.
- `bot.py` — запуск Telegram-бота; `mcp_server.py` — запуск MCP-сервера.

## Проверка

```powershell
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m compileall -q bot.py inventory_bot.py storage.py storage_types.py amounts.py panels.py inventory_service.py mcp_server.py
.\.venv\Scripts\python -m pytest -q
```

## Сервер

Пример пользовательского systemd-сервиса находится в `deploy/home-warehouse-bot.service.example`.
Замените `/path/to/home-warehouse-bot` на путь установки и настройте `.env` в этом каталоге.
Перед обновлением сохраните резервную копию SQLite-базы. Миграции применяются при запуске.
